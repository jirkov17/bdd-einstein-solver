# Решатель логических задач на BDD

[![CI](https://github.com/jirkov17/bdd-einstein-solver/actions/workflows/ci.yml/badge.svg)](https://github.com/jirkov17/bdd-einstein-solver/actions/workflows/ci.yml)

Модифицированная задача Эйнштейна, решённая через бинарные решающие диаграммы (BDD) на C++ с библиотекой [BuDDy](https://github.com/SSoelvsten/buddy). Курсовая работа по математической логике, СПбПУ, 2025.

Программа не перебирает варианты. Она строит одну булеву функцию, которая истинна ровно на решениях задачи, а BDD хранит эту функцию компактно. Поэтому решения считаются за миллисекунды, хотя после первой группы ограничений подходящих наборов порядка 10²⁸.

## Задача

9 объектов стоят в квадрате 3 × 3. У каждого объекта 4 свойства, у каждого свойства 9 значений, и у разных объектов значения одного свойства не совпадают.

```
0 1 2
3 4 5
6 7 8
```

В моём варианте соседи лежат на диагонали: сосед слева находится внизу слева, сосед справа — вверху справа. Например, у объекта 4 сосед слева 6, а справа 2. В варианте со склейкой левый край поля склеен с правым.

Ограничения задаются функциями `cond_1` … `cond_6`:

| Тип | Смысл | Формула |
|---|---|---|
| 1 | свойство k объекта i равно j | F ∧= p(k, i, j) |
| 2 | два значения разных свойств всегда принадлежат одному объекту | F ∧= ⋀ᵢ (p(k₁, i, j₁) ↔ p(k₂, i, j₂)) |
| 3 | слева или справа от объекта с одним значением стоит объект с другим | F ∧= ⋀ᵢ (p(k₁, i, j₁) ↔ p(k₂, сосед(i), j₂)) |
| 4 | такие объекты стоят рядом, слева или справа | F ∧= (тип 3 слева) ∨ (тип 3 справа) |
| 5 | значения свойства у разных объектов не повторяются | p(k, i, v) → ¬p(k, j, v) |
| 6 | каждое свойство принимает одно из 9 допустимых значений | ⋁ⱼ p(k, i, j) |

## Как устроено кодирование

- Значение каждого свойства хранится в 4 битах (2⁴ ≥ 9), всего 9 × 4 × 4 = **144 булевы переменные**.
- `p[k][i][j]` — BDD для высказывания «свойство k объекта i равно j», собранная из этих 4 битов.
- Ограничения добавляются в общую функцию через `&=`. После каждой группы программа печатает `bdd_satcount`, то есть сколько наборов ещё подходит.
- `bdd_allsat` обходит все решения. Каждое печатается построчно: `i: a b c d` — значения четырёх свойств объекта i.

## Сборка и запуск

Нужны CMake 3.16+ и компилятор с поддержкой C++17. BuDDy скачивается автоматически при конфигурации.

```bash
cmake -S . -B build
cmake --build build
./build/bdd_einstein            # спросит, нужна ли склейка: yes или no
echo no | ./build/bdd_einstein  # без вопросов
```

Сборка с AddressSanitizer и UBSan:

```bash
cmake -S . -B build-asan -DCMAKE_BUILD_TYPE=Debug -DENABLE_ASAN=ON
cmake --build build-asan
```

## Что изменено при публикации

Логика курсовой осталась прежней. Изменения отдельным коммитом:

- Комментарии перекодированы из Windows-1251 в UTF-8, `void main` заменён на `int main`. Теперь код собирается GCC и Clang, а не только MSVC.
- Исправлен выход за границы массива в `cond_3` для соседа справа со склейкой. Цикл начинался с верхнего ряда, у которого нет соседа сверху, и индекс `i - SIDE + 1` превращался в 4294967294. Ошибку нашли AddressSanitizer и UBSan, до исправления вариант со склейкой падал.
- Добавлены сборка на CMake и CI на GitHub Actions: сборка в Release и под санитайзерами, проверка числа решений в обоих вариантах.
